What is the difference between JPA and Hibernate?JPA (Java Persistence API):
A specification or set of guidelines defining Object-Relational Mapping (ORM) rules.Hibernate: An ORM framework that implements the JPA specification and provides extra proprietary features.2. How does Spring Boot auto-configure Hibernate?Starter Dependency: Including spring-boot-starter-data-jpa automatically triggers auto-configuration.Properties File: Spring Boot reads connection configurations from application.properties or application.yml.Auto-creation: It automatically creates the DataSource, EntityManagerFactory, and TransactionManager beans behind the scenes.3. Explain the difference between Session (Hibernate) and EntityManager (JPA).EntityManager: The JPA-standard interface used to manage the persistence context lifecycle.Session: The Hibernate-specific interface extending or wrapping the functionality of the standard EntityManager.🔄 Entity Lifecycle & State Management4. What are the 4 lifecycle states of an entity in Hibernate?Transient: The object is created (new) but not yet associated with a session or database row.Persistent: The object is associated with an active session and has a matching row in the database.Detached: The object exists in the database, but its tracking session has been closed or cleared.Removed: The object is scheduled for deletion from the database during the next flush.5. What is the difference between get() and load() methods?get(): Hits the database immediately and returns the actual object (or null if not found).load(): Returns a lazy-loaded proxy object and delays hitting the database until a property is accessed. It throws an exception if the row does not exist.6. What is the difference between update() and merge()?update(): Reattaches a detached object directly to the current session. It throws an exception if another instance of the same entity is already loaded in the session.merge(): Copies the state of a detached object onto a managed persistent object fetched from the current session.🚀 Performance Tuning & Optimization7. What is the N+1 SELECT problem, and how do you solve it in Spring Boot?The Problem: Occurs when you fetch a list of parent entities (1 query) and Hibernate executes separate queries (N queries) to fetch lazy-loaded child entities for each parent.Solutions:Use JOIN FETCH inside JPQL/HQL queries to pull parents and children in a single database trip.Use the @EntityGraph annotation above your Spring Data repository methods to specify dynamic fetch paths.Apply @Fetch(FetchMode.SUBSELECT) to fetch child collections in a second bulk query.8. How does Hibernate Caching work?First-Level Cache: Enabled by default at the Session level. It is single-threaded and keeps track of entities managed within the current transaction.Second-Level Cache: Configured at the SessionFactory level and shared across sessions. It requires external caching providers like Redis, Hazelcast, or Ehcache.9. What is Dirty Checking in Hibernate?Definition: An optimization feature where Hibernate automatically detects if an entity's fields have changed.Mechanism: During a transaction commit or session flush, Hibernate compares the entity's current state against its original snapshot and automatically executes an UPDATE statement without calling an explicit save method.🛡️ Advanced Quirks & Pitfalls10. Why does @Transactional sometimes fail or get ignored?Self-Invocation: If a non-transactional method calls a @Transactional method within the same class, the transaction fails silently.Proxy Limitation: Spring manages transactions using AOP proxy objects. We use FetchType.LAZY because fetching everything automatically by default is a bad practice.java@Entity
public class Author {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name;

    @OneToMany(mappedBy = "author", fetch = FetchType.LAZY)
    private List<Post> posts;

    // Getters and Setters
}

@Entity
public class Post {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String title;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "author_id")
    private Author author;

    // Getters and Setters
}
Use code with caution.Step 2: Write the JOIN FETCH Repository QueryInstead of using standard built-in Spring Data JPA methods like findAll(), write a custom JPQL query using the @Query annotation.java@Repository
public interface AuthorRepository extends JpaRepository<Author, Long> {

    // The magic happens here
    @Query("SELECT a FROM Author a JOIN FETCH a.posts")
    List<Author> findAllAuthorsWithPosts();
}
Use code with caution.Step 3: Trigger the Method in Your ServiceCall your custom repository method inside a transactional service layer.java@Service
public class BlogService {

    @Autowired
    private AuthorRepository authorRepository;

    public void displayDashboardData() {
        // This fires exactly ONE highly-optimised SQL query
        List<Author> authors = authorRepository.findAllAuthorsWithPosts();

        for (Author author : authors) {
            // No extra queries are fired here! The data is already in memory.
            System.out.println(author.getName() + " wrote " + author.getPosts().size() + " posts.");
        }
    }
}
Use code with caution.🔍 Under the Hood: What is Hibernate doing?Without JOIN FETCH (The Bad Way)If you just ran authorRepository.findAll() and looped through the posts, Hibernate would generate this behind the scenes:sql-- Query 1: Get all authors
SELECT * FROM author;

-- Query 2 to N+1: Fired repeatedly inside the loop for every single author ID
SELECT * FROM post WHERE author_id = 1;
SELECT * FROM post WHERE author_id = 2;
SELECT * FROM post WHERE author_id = 3;
Use code with caution.With JOIN FETCH (The Optimised Way)When you call findAllAuthorsWithPosts(), Hibernate uses an inner SQL join to stitch the tables together immediately:sql-- Exactly ONE query executed
SELECT a.*, p.*
FROM author a
INNER JOIN post p ON a.id = p.author_id;
Use code with caution.Hibernate reads this single, wide matrix result from the database and intelligently reconstructs your Java Object graph (Author objects containing their populated List<Post>).⚠️ Two Critical Rules for InterviewsNever use Pageable with JOIN FETCH for collections: If you try to pass a Pageable object into a JOIN FETCH query targeting a collection (List<Post>), Hibernate will pull all records into server memory and do the paging in Java. This can easily crash a production application.Difference between JOIN and JOIN FETCH: A regular JPQL JOIN simply filters the query results based on the relationship but leaves the collection uninitialised (lazy).
